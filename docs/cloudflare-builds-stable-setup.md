# MotoIndex Cloudflare Builds: stable connected configuration

MotoIndex uses GitHub Actions for validation and **manually approved** production releases. Cloudflare remains connected to GitHub for pull-request preview builds. Do not disconnect and reconnect the repository to fix build failures.

## Why this exists

Cloudflare Workers Builds does **not** honor the `build` command inside `wrangler.jsonc`. The Cloudflare Build command must itself run the OpenNext adapter to create `.open-next/worker.js`.

- Cloudflare **preview build command:** `npm run cf:build`
- Cloudflare **preview deploy command:** retain `npx wrangler preview` for the modern Worker Previews model, or `npx wrangler versions upload` if the project still uses the older preview model. Do not switch preview models automatically.
- Cloudflare **production trigger:** exclude `main` from Git-connected builds and use `npx wrangler versions upload` as a defense-in-depth non-promoting command.
- **Actual production deployment:** keep `.github/workflows/cloudflare-production-deploy.yml`, launched manually from reviewed `main`.
- **Production guard:** keep `scripts/reject-workers-git-production-build.mjs` unchanged; it intentionally prevents automatic Workers Builds from promoting unknown/production branches.

Cloudflare documents that build triggers can be configured through the Workers Builds API without deleting the Git repository connection:
https://developers.cloudflare.com/workers/ci-cd/builds/api-reference/

## One-time review and apply, without reconnecting

A restricted, manual workflow is provided at `.github/workflows/cloudflare-builds-reconcile.yml`. It is available when reviewed onto `main`.

1. In GitHub Actions, open **Inspect or repair MotoIndex Cloudflare Builds**.
2. Select **inspect**. Optionally enter the failed build UUID shown in the Cloudflare build link. This reads the current triggers, actual build commands, and a sanitized error-category summary without printing raw logs.
3. Inspect reports **all existing triggers**, including accounts with only one trigger or a nonstandard configuration. It also reports the suggested safe changes when it recognizes exactly one production and one preview trigger for `motoindex-ph`. If the account has a custom trigger or unsafe preview deploy command, **apply** refuses to guess while **inspect** remains read-only and useful.
4. Select **apply**, enter `KEEP_GITHUB_CONNECTED`, and run the workflow from **main**. The protected `production` GitHub environment controls access to the token.
5. Run **inspect** again to verify the recorded state, then retry the affected Cloudflare preview build. Verify its branch Preview URL. GitHub CI and browser QA must also remain green.

**Inspection is possible before this draft PR merges.** In a trusted local checkout of the draft branch, install no new dependencies and set `CLOUDFLARE_ACCOUNT_ID` and `CLOUDFLARE_WORKERS_CI_TOKEN` as shell environment variables, then run:

```bash
node scripts/reconcile-cloudflare-builds.mjs inspect 0ac31477-dab4-4ebb-950c-e38452aa2ba7
```

The UUID is the failed Cloudflare build for draft PR #517. Use the `inspect` operation only until the actual build log has been reviewed; do not run `apply` on an unreviewed feature branch.

This workflow uses `CLOUDFLARE_ACCOUNT_ID` and a Cloudflare API token. Prefer the protected-environment secret `CLOUDFLARE_WORKERS_CI_TOKEN` with Workers CI Read and Write plus Workers Scripts Read permissions (the last permission resolves the Worker's immutable tag); it falls back to the existing `CLOUDFLARE_API_TOKEN` if that token already has those permissions. Do not place credentials into `wrangler.jsonc`, commit them to git, or print raw build logs.

The reconciliation script **only GETs and PATCHes existing Workers Builds triggers**. It never calls repository-connection APIs, deletes triggers, invokes a production deployment, or switches the legacy preview model to Worker Previews. If a trigger is missing or settings differ from the expected shape, it fails closed rather than rebuilding a connection.

## External checks and release gating

The GitHub check `Workers Builds: motoindex-ph` is generated by Cloudflare, not by this repository's GitHub workflows. A failed historical check cannot be turned green by editing the PR description or removing a GitHub workflow. If this check is required by a branch ruleset, verify that a **new successful preview build** has reported a passing check for the PR head before merging. Do not bypass required checks just to ship this change.

Cloudflare dashboard build history is still the source of full build logs. The authenticated workflow shows only safe error classifications to avoid exposing secrets in GitHub Actions logs.
